# FMF Display Controller (fixed copy)

蛍光磁性流体-エラストマー (FMF) ディスプレイの統合制御コード。
RGB → 駆動電圧/電流変換、キャリブレーション、フレーム送信プロトコルを含む。

これは原典に対する**修正版**である。原典は変更していない。

## 修正点

2026-11-06 の検証で見つけた表示系の欠陥 4 点:

1. LUT の層順 (R/B 取り違え) を宣言通りの [青, 緑, 赤] に統一
2. 駆動×消光の合成が非単調だった問題 — 光学消光モデルを物理として残し、
   駆動マップ側を反転 (黒画素が最高電圧)
3. コイル電流のクリッピング (4096 色中 4092 色) — 独立した低電圧
   ドメインで再計算し、内部クリップ 0 に
4. プロトコルの CRC 順序 / uint8 ラップ / LEN 溢れを宣言フレームに合わせて修正

2026-11-07 の堅牢化 1 点:

5. `load_calibration()` がキャリブレーション JSON のキーを `eval` で
   復元していた — 他人の作った JSON を読むと任意コード実行になるため
   `ast.literal_eval` に置換 (キーはタプルの文字列表現のみ)

## 検証

`fmf_verify_fixed.py` を実行すると 7 件の照合が走る
(sRGB/CIE 標準値との一致、修正 4 点の再確認)。
2026-11-07 時点で 7/7 通過。加えてキャリブレーションの
保存→読込の往復 (LUT 343 件) と、悪意あるキーを持つ JSON が
実行されずに拒否される事を確認済み。

## 範囲

実機は存在しないため、検証は「ファイル自身の宣言・物理標準値との
一致と内部整合性」まで。物理モデル自体の妥当性は主張しない。
駆動マップの向き (修正 2) は、消光モデルを物理として採用した上での
判断であり、意図が逆であれば修正は光学モデル側に入る。
